# critic EV case study（2026-10-14）

> 来源：原 README 第 16.14.7 节。拆分前的全文见 git 提交 b8d95027 中的
> docs/research/2026-10-09-tau2-high-baseline-audit/README.md。

**要回答的问题**：critic-only 训练了好几轮（479、499、510），验证集上的 EV 一直在 0 附近，最好也只有 0.1–0.2。是 critic
没学好，还是数据里本来就没有可学的东西？Codex 和 Claude 各做了一份分析，互不参考，只用已有数据，不花 API。

**结论**：

- Airline：数据里有可学的信号，critic 学到了"哪条更可能成功"的排序，但预测值几乎不动，EV 因此很低。更像是训练强度（学习率 × 步数）不够，不是没信号。
- Retail：本来就没多少可学的，训练数据里失败的例子也太少，EV 接近 0 是意料之中。
- 验证集只有 60 条轨迹，单个验证点的 EV 误差约 ±0.1：r2 第 55 步的 0.18 和最后一步的 0，差别很可能只是噪声。

## 先说清楚我们在看哪个数

EV 的定义和"上限"的含义见 `ev-ceiling-explainer.md`。这里补充验证报告里 EV 的具体算法，后面的分析都建立在它上面：

- **在哪些位置算**：一条验证轨迹里，agent 说的每一个 token 都有一个 critic 预测 $V_t$，目标都是这条轨迹最后的成败 $R$（0 或 1）。EV
  把所有这些 token 放在一起算，长轨迹占的权重更大。它不是"只看对话开头"，[ev-ceiling.md](ev-ceiling.md) 算上限时假设 critic
  只知道题目身份。
- **扣掉了整体偏移**：如果 critic 对所有 token 都多预测 0.3，EV 不受影响，这部分单独记在"偏移"一栏。所以 EV 只衡量 critic
  能不能区分"这条比那条更可能成功"，以及区分的幅度对不对。
- **"单点 EV"**：指某一步的 checkpoint 在这 60 条验证轨迹上算出来的那一个数，例如"第 55 步 Airline 0.179"。

## 分析 1：一个验证点的 EV 有多准

**为什么要看**：Airline 只有 20 条验证轨迹、Retail 40 条，其中失败的只有 5–10 条。换一批轨迹，EV 可能差很多。不知道误差，就没法判断 "第
55 步比第 80 步好"是不是真的。

**怎么做（bootstrap）**：从这 20 条轨迹里有放回地随机抽 20 条（有的会被抽到两次，有的抽不到），重新算一次 EV；重复 2 万次，看 EV
在多大范围里晃动。中间 95% 的范围就是区间。比较同一个 run 的两个验证步时，两步用同一组抽样（配对），这样轨迹本身的差异会互相抵消。

**结果**：

| run / 步 | Airline EV \[95% 区间\] | Retail EV \[95% 区间\]   |
| -------- | ----------------------- | ------------------------ |
| 499 / 94 | 0.025 \[0.002, 0.070\]  | −0.001 \[−0.024, 0.007\] |
| 510 / 60 | 0.168 \[−0.039, 0.349\] | 0.028 \[−0.037, 0.064\]  |

- 510 的 Airline 区间从 −0.04 到 0.35，宽度约 0.4。第 20 步到第 60 步提高了 0.10，但配对区间 \[−0.05, 0.23\] 包含
  0，分不出是真提高还是噪声。
- 499 的区间很窄，不是因为它可靠，而是它的预测几乎是常数，换哪批轨迹都差不多是 0。
- Retail 更极端：就算有一个完美知道每道题成功率的 critic，在这 40 条上的 EV 也可能落在 −0.2 到 0.62 之间（模拟结果）。Retail
  验证集分不出"学到了"和"没学到"。

## 分析 2：critic 学到排序了吗

**为什么要看**：EV 低有两种可能。一是 critic 根本分不清成功和失败；二是它分得清，但预测值只差一点点（比如成功的预测 0.85、失败的预测 0.83），EV
依然很低。两种情况的修法完全不同，要分开看。

**怎么看排序：AUC**。随机挑一条成功的轨迹和一条失败的轨迹，critic 给成功那条的预测更高的概率就是 AUC。0.5 等于瞎猜，1
是完全排对。它只看排序，不看数值差多少。这里用每条轨迹所有 token 预测的平均值来排。

**怎么看"差多少"：最优仿射校准**。把 critic 的预测线性变换成 $aV + b$，选 $a$、$b$ 让 EV 最大，看最好能到多少。直觉是：如果 critic
排序对、只是幅度太小（$a$ 需要很大），拉伸之后 EV 会明显上升。$a$ 和 $b$ 是在验证集上直接拟合的，结果偏乐观，只用来诊断，不是能用的修法。

| run / 步 / 领域    |     EV |  AUC | 轨迹之间预测的差别（标准差） | 需要放大的倍数 $a$ | 用轨迹平均值拉伸后的 EV |
| ------------------ | -----: | ---: | ---------------------------: | -----------------: | ----------------------: |
| 499 / 94 / Airline |  0.025 | 0.88 |                        0.017 |                 12 |                   0.175 |
| 510 / 60 / Airline |  0.168 | 0.83 |                        0.114 |                  2 |                   0.274 |
| 499 / 94 / Retail  | −0.001 | 0.48 |                        0.007 |                  3 |                   0.004 |

- 499 的 Airline：AUC 0.88，排序基本是对的；但各条轨迹的预测只在 0.77–0.92 之间，标准差 0.017，而成败标签的标准差是 0.49。要放大
  12 倍才对得上。
- 510 的 Airline 幅度大得多（标准差 0.114），所以 EV 也高。
- Retail 的 AUC 0.48，和瞎猜一样。

两份报告在这里的数字不同，原因是拉伸的对象不同：

- Claude 先把每条轨迹的预测换成它的平均值再拉伸（上表最后一列），499 能到 0.175。
- Codex 直接拉伸每个 token 的预测，499 只到 0.044，510 只到 0.18。

差别说明：critic 的预测在一条轨迹内部来回波动，盖住了轨迹之间的排序。另外，轨迹平均值用到了轨迹后面的 token，对话进行中的 critic 拿不到，所以 Claude
那一列只说明"排序存在"，不是 critic 实际能达到的值。

## 分析 3：为什么预测几乎不动

这一条是推测，没有做干预实验验证。

- value head 是 $V = w^\top h + b$。499 训练完，$w$ 的大小（范数）只有 0.0015。
- 我们用的优化器 Adam 有个特点：不管梯度多大，每一步每个参数大约只移动一个学习率那么多。学习率 5e-6、94 步，每个参数最多移动约 5e-4。$w$ 从 0
  出发，94 步之后自然还很小。骨干网络的权重在 94 步里也只变了 0.3–0.5%。
- 训练 batch 上的 EV 和验证集上差不多，说明不是"在训练集上学会了、换到测试集就不行"（过拟合），而是训练集上也没学够（欠拟合）。
- 510 的数据里失败样本更多，每一步的梯度信号更强，$w$ 也更大（0.0024），EV 更高。

## 分析 4：信号是不是真的在数据里

**为什么要看**：如果数据里根本没有能预测成败的信息，再怎么训练也没用。

**怎么做**：用一个最简单的文本分类器（词袋逻辑回归：只统计轨迹里每个词出现了几次，用这些计数预测成败），在 4007 条已存的训练 rollout
上训练，在同一批验证轨迹上测。它不懂语序，也不懂语义，如果它都能预测，说明信号在数据里。

| 领域       | 只看第一句用户消息 |       看完整轨迹 | 五个前缀长度平均 |
| ---------- | -----------------: | ---------------: | ---------------: |
| Airline EV |               0.20 |             0.48 |             0.24 |
| Retail EV  |  −0.01（AUC 0.46） | 0.19（AUC 0.85） |             0.06 |

- Airline：这个简单分类器比 critic 高 0.07–0.2。信号在数据里，critic 没学到。
- Retail：开头几乎什么都预测不了；要看到对话后面才有一些信号，平均下来只有 0.06。再加上训练数据里 Retail 失败的轨迹很少（499 只有 29/674
  条，510 有 46/442 条），critic 学不到是正常的。

## 分析 5：ev-ceiling.md 的上限要打折扣

[ev-ceiling.md](ev-ceiling.md) 的"上限"（Airline 0.61、Retail 0.20）是假设 critic
一开始只知道"这是哪道题"。Codex 指出，同一道题每次运行时用户的第一句话并不完全一样，所以 critic 在第一个 token
其实知道得更多一点，这个上限并不严格。另外，同一道题内部的波动不全来自用户，policy 和 judge 也有一部分。Claude 用每题 7 次的数据重算：Airline
0.59 \[0.36, 0.78\]，Retail 0.24 \[0.07, 0.39\]，和原来接近。

## 下一步：先离线做实验，不花 API

现有数据分不清"critic 的特征里有信号，只是训练不够"和"特征里本来就没有"。两份报告都建议先用已存的 rollout 离线做实验：

| 实验         | 做法                                                                               | 要回答的问题                                           | 估计成本          |
| ------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------ | ----------------- |
| 线性探针     | 让原始 Qwen3.5-4B 在已存 rollout 上前向一遍，存下隐状态，在 CPU 上只训练一个线性层 | 模型的特征里有没有能预测成败的信息                     | 0.3–3 GPU 小时    |
| 植入信号对照 | 把标签换成轨迹里看得见的东西，例如"工具返回里有没有 Error"，再用原设置训练 critic  | 这套训练管线在这个预算下，能不能学会一个明确存在的信号 | \<0.5 GPU 小时    |
| 离线重放     | 用 510 的数据重训 critic，分别用原学习率、head lr 1e-4 加 warmup、骨干 lr 2e-5     | 能否复现差结果；加大学习率能否提高幅度                 | 每组约 5 GPU 小时 |

这些实验都需要先写一个"从已存 rollout 训练 critic"的入口，不启动推理服务和用户模拟器。目前还没有。

两份报告认为最有希望的修法是提高 head 的学习率。[value-head.md](value-head.md) 因为 head lr 1e-4 让整体水平每个 batch
跳一次而放弃过，再用时要加 warmup，或先固定 bias。其次是改验证口径：每题采 3 次以上，同时报告 AUC 和区间。不推荐继续加简单题，它们只能教会 critic
整体水平，而水平已经由初始化定好。
