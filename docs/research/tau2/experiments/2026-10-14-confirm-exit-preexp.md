## 1. 目的

动机里"不可靠用户会让训练学错方向"（problem-and-plan §1 第 2 种伤害）目前只是推理。本实验在不训练的前提下回答三个问题：

1. 在 agent 请求确认、写操作尚未执行的那一刻，各用户模拟器直接结束对话的概率 $\rho$ 有多大。
1. 这种离开有多少是"同一个对话前缀下也会随机发生"的，有多少由前缀决定。
1. agent 换一种确认说法，$\rho$ 会不会变。

## 2. 背景：为什么 $\rho$ 本身就是"学错方向"的激励

- policy 要求写操作前列出细节并拿到明确的 yes（`airline/policy.md:7`、`retail/policy.md:16`）。
- 评分不检查这一点：fixed-v3 的 Airline 123 条、Retail 61 条 NL 断言里没有一条检查写前确认（2026-10-14 核对），reward
  主要看 DB 终态。v3 轨迹里少数未经确认的写操作照样得分（例如 DeepSeek 5 个这样的 episode 中 4
  个成功，按"写操作前最后一条用户消息没有肯定词"粗略判定）。
- 所以对同一个任务，记确认后用户离开的概率为 $\rho$，用户说 yes 之后任务成功的概率为 $q$，则

$$
\mathbb{E}[R \mid \text{先确认}] \approx (1-\rho)\,q,\qquad \mathbb{E}[R \mid \text{不确认直接写}] \approx q,\qquad \Delta = \rho\, q .
$$

只要 $\rho > 0$，reward 就偏向"不确认"，与 $\rho$ 是否随 agent 的说法变化无关。但确认也有收益：agent
列出的细节有错时，用户在确认环节可以纠正（例如"不是这个商品"），不确认就直接写错。记这部分收益为 $g$（确认环节纠正了 agent 的错误、最终成功的概率），净激励为

$$
\Delta_{\text{net}} = \rho\, q - g .
$$

$\Delta_{\text{net}} > 0$ 时 reward 偏向跳过确认。本实验测 $\rho$、$q$、$g$；训练会不会真的利用这个激励，由 X1 检验。

## 5. 设置

### 5.1 确认节点（只看前缀，不看之后发生了什么）

一个确认节点是一对相邻消息 $(m_i, m_{i+1})$，其中 $m_i$ 是 agent 的纯文本消息（无工具调用），$m_{i+1}$ 是用户回复，并满足：

1. $m_i$ 匹配请求确认的说法（confirm、proceed、go ahead、shall I、would you like me
   to、"(yes)"），并提到写操作的动词（cancel、modify、exchange、return、book、update、change）；
1. $m_i$ 之前，本次要确认的写操作还没有执行。判定方式：$m_i$ 中出现的订单号或预订号，在 $m_i$ 之前没有对应的写工具调用成功。

规则只用 $m_i$ 及其之前的信息，避免按结果挑样本。执行时先在 50 个随机节点上人工核对规则精确率（第 10 节记录），低于 0.9 就修改规则并记录。

### 5.2 抽样

- **随机样本**：每个模拟器从全部确认节点中按种子 20261014 抽 80 个，按领域保持 Airline : Retail = 1 : 2，每个 episode 最多
  1 个。总体估计（H0、H1）只用随机样本。
- **补充样本**：原回复是控制符的确认节点（各模拟器 U1 失败对应的节点）若不在随机样本中，全部补入，单独标记。只用于 H2 的前缀内分析，不进入总体估计。

### 5.3 重采样

- 对每个节点，用 `UserSimulator`（任务的 `user_scenario` + 通用 guideline，与原运行同一代码）还原到 $m_i$
  为止的用户状态，生成下一句用户回复，**K = 8 次**。
- 先做一致性自检：对 GLM（短 prompt 下 T=0 输出固定）的 10 个节点，检查重采样能否逐字复现原回复；不能复现时，检查还原的 system prompt
  和消息序列是否与原运行一致，再继续。

### 5.4 措辞干预（只对 Turbo、Lite 的随机样本）

| 版本 | $m_i$ 的改法                                                                                                                                                             |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| S0   | 原文                                                                                                                                                                     |
| S1   | 原文末尾加一句固定文本："Please reply yes to confirm. Nothing has been changed yet; I will make the change only after you confirm, and I will tell you when it is done." |

S1 是确定性改写，不改动原文里的商品、价格、ID。只测这一种，回答"说法能不能改变 $\rho$"的存在性，不搜索最优说法。

### 5.5 回复编码（规则，预先登记）

| 类别       | 规则                                                          |
| ---------- | ------------------------------------------------------------- |
| END        | 回复含 `###STOP###`、`###TRANSFER###` 或 `###OUT-OF-SCOPE###` |
| END_AFFIRM | END 中同时含肯定用语（即 U1 形态）                            |
| AFFIRM     | 不含控制符，含肯定用语                                        |
| OTHER      | 其余（改要求、提问、拒绝）                                    |

离开率 $\rho$ 按 END 计算，同时报告 END_AFFIRM 的比例。在 50 条随机回复上人工核对编码，记录一致率。

### 5.6 指标

- $\rho$：随机样本上的平均离开率，按模拟器、领域报告，带区间。
- $q$：原运行中原回复为 AFFIRM 的确认节点，其 episode 最终成功的比例。
- $g$：原运行中原回复为 OTHER、且 agent 随后修改了待执行的写操作参数（与 $m_i$
  中列出的细节不同）并最终成功的确认节点所占比例。它是确认环节纠错收益的估计，偏高（用户改要求不一定是在纠正 agent 的错误，也可能是任务剧本要求改主意），所以
  $\Delta_{\text{net}}$ 偏保守。
- $\Delta = \rho q$、$\Delta_{\text{net}} = \rho q - g$，按模拟器报告，带区间。
- 前缀内占比：对每个前缀的 8 次结果算 $\hat p_j$；总方差 $V = \bar p(1-\bar p)$，前缀内方差
  $W = \operatorname{mean}_j\big[\tfrac{K}{K-1}\hat p_j(1-\hat p_j)\big]$，前缀内占比
  $= W / V$。用随机样本加补充样本各报告一次。
- 措辞效应：每个前缀 S1 与 S0 的离开率之差，按题配对 bootstrap。

### 5.7 规模与费用

| 部分                                  | 调用次数                |
| ------------------------------------- | ----------------------- |
| S0：4 个模拟器 × 约 80–110 个节点 × 8 | 约 3,000                |
| S1：Turbo、Lite × 80 × 8              | 约 1,300                |
| 合计                                  | 约 4,300 次单轮用户调用 |

Lite、GLM 走火山订阅；Turbo 按 v3 运行的配置走按量付费；DeepSeek 走官方 API。每次调用的 prompt 约 3–8k token。并发：GLM
不超过 32，其余不超过 64。

## 6. 结果怎么用（预先写下）

| 结果      | 对动机的含义                                                                                                                                                                                                                                            |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1 成立   | 论文可以写成：评分不检查确认时，不可靠用户使"跳过确认"多得 $\Delta$ 的期望 reward，并给出各模拟器的数值。X1 再检验训练是否真的学会跳过确认                                                                                                              |
| H1 不成立 | 确认节点的离开太少，通过这条路径学错方向的说法很弱；动机转向其他用户失败（U3 偏离）和方差                                                                                                                                                               |
| H2 成立   | 离开大多无法从对话前缀预测，属于第 1 种伤害（方差），16.13 拆出的"用户意外"有实际的量                                                                                                                                                                   |
| H2 不成立 | 离开主要由前缀决定，critic 原则上能学到，16.13 能去掉的部分很小，方法的贡献要另找                                                                                                                                                                       |
| H3 成立   | agent 可以通过说法预防一部分离开：这部分 U1 不再是"agent 无能为力的用户错"，而是 agent 能影响的，问题陈述里"用户单方面造成"的范围要相应缩小（只剩 S1 下仍然发生的离开）。这条适应本身无害；16.13 的 $U_t$ 在看到说法之后预测，能把这部分记到 agent 身上 |
| H3 不成立 | 说法不影响离开，离开对 agent 来说是外生的                                                                                                                                                                                                               |

## 7. 设计 review（Claude，2026-10-14）

**有用吗。** 有用，但作用是巩固机制、决定主张，不是动机的主证据。H1
能把"学会少确认"从推理变成一个有数值的激励（$\Delta_{\text{net}}$），可以写进论文的机制段；H2、H3 决定主张是"降方差"还是"纠偏"，以及 U1
有多少算"用户错"。"不可靠用户伤害训练"本身仍然只有 X1 能证明。

**有效吗。** 固定前缀重采样是真正的受控测量：同一个前缀，只有用户的采样不同。这比现有的"同 trial 配对"可靠，后者不共享随机数。主要的效度风险和处理：

| 风险                                                             | 处理                                                                                      |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 还原的用户状态与原运行不一致，测到的不是同一个用户               | H0 作为前提；GLM 逐字复现自检（5.3）                                                      |
| 只算确认的成本、不算收益，高估激励                               | 加入 $g$ 和 $\Delta_{\text{net}}$（5.6、H1）                                              |
| 确认节点规则误收"已完成后问还有什么需要"的消息，那时离开是合法的 | 规则要求写操作尚未执行，并人工核对 50 个节点的精确率（5.1）                               |
| 按结果挑样本                                                     | 规则只看前缀；总体估计只用随机样本，补充样本单独标记（5.2）                               |
| S1 只有一种改法，且明说"还没改"，效应可能偏大                    | 只用来回答"说法能不能改变 $\rho$"，不外推成最优说法；H3 成立时按第 6 节缩小"用户错"的范围 |
| 运行后服务端可能变化（v3 运行在 10-12、10-13）                   | H0 比较的就是同一批前缀上的新旧离开率，偏移会在 H0 暴露                                   |

**仍然管不到的。** (1) 激励存在不等于训练会利用：step 0 的 agent 几乎总是先确认（v3 中未确认就写的不到
4%），训练能否探索到"跳过确认"并被强化，要看 X1。(2) 模拟器的离开率不等于真实用户的离开率，论文里要说明这是代理。

## 8. 不在本实验范围

- 训练是否真的利用"跳过确认"的激励：X1。
- 其他用户失败类型（U3 偏离、U4b 提前结束）的前缀重采样：等本实验验证流程可行后再扩展。
- 真实用户确认后离开的比例：需要真实数据或文献，本实验不涉及。
