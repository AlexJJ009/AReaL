# 带剧本的用户错误 judge：离线验证

**推荐 G+T 用于离线筛查候选；现有结果不足以支持直接自动截断训练轨迹。** 主模型 Flash 在 v3 上，G 的 precision/recall 为 **48.1% / 22.0%**，G+T 为 **56.1% / 81.5%**；v4 对应为 **43.0% / 22.2%** 和 **46.1% / 79.9%**。补充 trigger 后，v3 端到端最早人工引用对齐率从14.9%升至69.0%（±2消息：17.3%→73.8%）。这是证据对齐代理值，不能当真实首错准确率。

提升主要来自控制符错误：G+T 检出 v3 全部77条 U1、11条失败 U7a；但 U3 仅38/66。G+T 也将 v3 的29/29、v4 的45/45条成功侧提前转接标为用户错误，且会误读已经执行过的转接工具。40条分歧复读中，二元判断错误为 G 36条、G+T 9条；计入错误位置或理由后分别为39条、23条。本轮建议更正1条原主因归属，未改源标签。

本实验的主指标把“用户致败”当正类，但两个 prompt 检查的是“任何用户违规”。成功轨迹中的提前 TRANSFER、先被 agent 错误破坏后才出现的用户违规，都会成为主指标的误报。这些误报不能一律解释为模型看错；报告分别保留二元得分、成功异常和逐条复核结论。

## 1. 任务、数据和边界 {#goal}

目的是检验带剧本的 LLM judge 能否发现用户模拟器的错误，并为后续训练提供首次错误消息位置。本次只离线读取轨迹；没有训练、使用 GPU 或修改仓库代码和文档。全部脚本、缓存和结果保存在本目录。

v3 纳入 428 条人工标注及 200 条随机普通成功，合计 628 条；v4 纳入 700 条标注及 360 条随机普通成功，合计 1,060 条。每个运行、每个领域从未标注且成功的 completed 轨迹中固定种子抽 20 条；已标 U6/提前 TRANSFER 的成功全部纳入。v3 和 v4 的标签及分数均保留原样，不用本轮重读结果改写主指标。

| 版本 | episode | 用户致败正类 | agent 致败负例 | benchmark 致败负例 | 普通成功 | U6 成功 | 提前 TRANSFER 成功 |
| ---- | ------- | ------------ | -------------- | ------------------ | -------- | ------- | ------------------ |
| v3   | 628     | 168          | 204            | 13                 | 200      | 14      | 29                 |
| v4   | 1060    | 194          | 406            | 35                 | 360      | 20      | 45                 |

主正类定义为 `score < 1 且 primary 以 U 开头`。成功侧 U6/U7a 属于成功异常，仍是“无致败用户错误”的负例。全部失败和成功异常都纳入，普通成功仅抽样，因此主表 precision 是本评测集上的 precision，不是全运行部署时的 precision。表后另给按普通成功抽样概率还原的估计。输入文件、轨迹和 task 的 SHA256、种子、运行路径见 [dataset_manifest.json](dataset_manifest.json) 和 [dataset.jsonl](dataset.jsonl)。

## 2. 结果总览 {#progress}

两个变体各运行 Flash 1,688 次；Pro 仅在冻结的 200 条分层子集上各运行一次，共 3,776 条判决。子集按版本各 100 条，再按运行×领域×二元标签分层轮转抽取；两模型和两变体使用相同 episode。所有请求 temperature=0，显式关闭 thinking；两种模型名与响应实读值的检查见验证结果。

## 3. Prompt 与实现选择 {#decisions}

G 只要求检查用户是否违反剧本或 guideline、找第一条错误，并约束 JSON、0-based 编号和逐字引文；没有加入 τ² 特有错误清单。G+T 在相同 system prompt 后追加 v3 REPORT 中 U1、U3、U4/U4b、U5、U7a 的定义和各一个短例。除这段附加文字外，输入、模型参数和输出规范相同。自由文本 category 在收集后用固定规则映射为 U 码，不读取人工标签；二元指标不依赖该映射。映射只是描述性归类，精确类别匹配另存 metrics.json，不冒充新的独立标注。

每次输入包含完整 `task.user_scenario`（含 instructions 内的 reason_for_call、known_info、unknown_info、task_instructions 等原字段）、guideline 原文、完整编号对话，包括所有工具调用和返回。保留 content 与 tool_calls，去掉 raw_data、计费、时间戳和评分等非对话元数据，不向 judge 提供人工 primary/rationale 或 gold。0-based 消息编号直接对应原 JSON 的 messages 数组，工具消息也计数。完整模板见 [judge_prompts/](judge_prompts/)。

AutoForge 论文 [附录 A.1](https://arxiv.org/html/2512.22857#A1.SS1) 的 judge 检查用户是否返回错误、超出意图范围的信息，以及被询问时是否正确提供信息或表示不知道，只输出整条 True/False。本任务沿用剧本信息一致性检查，加入 guideline 和首错位置输出。论文正文称将模拟用户错误轨迹整条 mask；这并不证明本次消息级截断有效。论文及 prompt 原文已归档至 [sources/](sources/)。GitHub 仓库检索没有找到能确认属于该论文的公开代码；同名 AutoForgeAI/autoforge 的 README 是 Claude SDK 编程 agent，已排除，未声称读过论文代码中的 prompt。

本次仅使用 DeepSeek 官方 `deepseek-flash` 和 `deepseek-v4-pro`；旧 260910 的部分判决和缓存已移入 `superseded-260910/`，不进入本报告的指标或费用。

API 请求以 endpoint+请求体的 SHA256 为缓存键；请求与所有 HTTP 回复（含 429）分别落盘，鉴权 header 不保存。重跑优先使用已有成功回复，不因规范性错误重新付费提问。当前官方缓存内全部3,776次HTTP尝试均为200；全量重跑3,776次均命中成功缓存、没有新增请求，日志见 `logs/cache-replay.log`。

## 5. 影响结论的限制 {#scope}

- v4 含按题批量归因，只作近似真值；本轮随机复读的更正不会自动使剩余 v4 标签可信。v3、v4 指标始终分开。
- 检测任何违规与判定用户致败不等价。把本次 judge 直接用于 mask/截断，会在成功异常及 agent 已先致败的路径上产生不同训练语义；本次没有训练或干预重跑证明收益。
- 人工证据引用不是专门的首错标注。位置表测的是证据对齐；特别是多引用 v4，不能当成真实首错准确率。
- 40 条来自分歧样本，复读者只有本轮主 agent；它估计的是这些分歧如何解释，不能推算全体标签错误率或多人一致性。
- 普通成功只抽 20/领域/运行，precision 受采样比例影响。全运行加权估计仍受抽样误差和未标注成功中的隐性违规影响。
- G+T的触发定义和例子来自v3，两个版本也沿用同一组60道题；这不是未见任务上的泛化检验。类似retail:79的另一只瓶子真实颜色不在剧本中，轨迹若未查到该订单，judge还缺少独立核验环境事实的信息。

## 6. 交付与使用边界 {#next_steps}

G+T 可作为后续消息级用户违规检测的候选基线；当前配置建议先离线筛查并保留证据供复核。用于自动截断前，需先确定要截“第一条任何违规”还是“致败的用户错误”，并为一批轨迹专门标注首错位置；本实验的主指标和代理位置指标不能替代该决定。

交付包含 [judge_prompts/](judge_prompts/)、[judgments.jsonl](judgments.jsonl)、[metrics.json](metrics.json)、[run_judge.py](run_judge.py)、[analyze.py](analyze.py)、[build_report.py](build_report.py)、[validate.py](validate.py)、[API 缓存](api_cache/) 和 40 条复读/20 条误报明细。复现命令：

```bash
PY=/data_storage/yl_test/lgx/data-1/code/_worktrees/AReaL/codex-sao-math/.venv/bin/python
OUT=/data_storage/yl_test/lgx/data-1/code/_artifacts/AReaL/codex-sao-math/tau2-user-error-judge-20261018
"$PY" "$OUT/run_judge.py" prepare
"$PY" "$OUT/run_judge.py" run --models flash pro --concurrency 32 --flash-interval 0
"$PY" "$OUT/analyze.py"
"$PY" "$OUT/build_report.py"

```

按本任务“独立完成、不启 sub-agent”的明确要求，报告由主 agent 自行作两遍阅读；没有独立报告 Judge，也不声明该流程的独立评审 PASS。仓库只读要求优先，未运行会修改仓库排除规则的正式报告初始化。验证结果见 [validation.json](validation.json)。
