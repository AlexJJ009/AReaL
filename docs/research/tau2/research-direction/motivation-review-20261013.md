## 3. 审稿人可能的质疑（按严重程度）

1. **评测差异不等于训练损害。**（两份都列为第一）[problem-and-plan.md §3](problem-and-plan.md)
   自己写了这条，至今没有训练对照。而且这个现象不新：AutoForge（2512.22857）§4.3 已经给出 with/without 用户错误 mask
   的训练曲线，不加 mask 后期下降。这对"问题存在"是有利的先例，但意味着现象本身不能当贡献，新意必须来自设定或方法。
1. **证据是模拟器 bug，设定是真实用户。** U1 是模拟器在同一句里发
   `###STOP###`，真人不会这样做；真人中途离开、改主意可能是合法行为，不能按"违反剧本"判为不可靠。Codex 补充：只观察对话、reward 和用户 ID
   时，"用户不可靠"和"任务难 / agent 能力不足 / 合法改意"一般不可辨识；critic 也不是单条 rollout 的数学必需品（REINFORCE 加历史
   baseline 也可行）。**[problem-and-plan.md §1](problem-and-plan.md) 必须先定研究对象是哪一种。**
1. **方法管的噪声和 case study 找到的问题不是同一个。**（Codex
   S2）[problem-and-plan.md §4](problem-and-plan.md) 在 $U_t$
   准确时保留的是**当前用户环境**下的期望梯度。如果当前用户分布本身偏离目标用户分布，降方差只会更稳定地优化这个偏离的目标。
   - **更正 Claude 的检验 2**：Claude 发现 47 个出现过 U1 的（模拟器、题目）组合中，31 个只在 4 次里出现 1 次，据此说"U1
     主要是随机的，属于问题 A"。这个说法不准确，随机发生的违规也可能有偏。准确的分法是：
     - 如果提前结束的概率 $\rho$ 与 agent
       动作无关，$\mathbb{E}[R \mid a] = (1-\rho)\,R^*(a)$，只把信号整体缩小，不改变最优策略，伤害只在有限样本效率上；
     - 如果 $\rho$ 随 agent 的说法变化（例如某种确认方式更容易触发结束），就会改变最优策略，属于学错方向。
   - 现有数据分不开这两种情况，要靠固定前缀重采样（第 4 节 E2）来回答。
1. **最便宜的修补没先做。**（Codex S5）U1 直接违反"任务完成后才 STOP"的通用规则，可以先试：在 user prompt 里写明"授权不等于完成"，或者让
   executor 区分"收到授权"和"任务结束"。如果这样就能消掉 U1 和训练损失，结论应收窄为"模拟器/评测器的可靠性问题和工程修正"，而不是需要新的 RL 方法。
1. **单一 LLM 标注者。** Codex 复读 19 条：15 条支持原标签，4 条应标为共同责任或歧义（Qwen retail:38 t0、Lite
   retail:100 t0、Qwen retail:77 t2/t3）。Qwen 的 51 个 U3 是"用户造成失败"最大的一块，也是边界最主观的一块。
1. **统计与随机性表述过度。** Qwen 自部署那组，360 对重复轨迹的首处分叉有 188 对在 actor
   一侧，[user-simulator.md §2](../user-simulator.md) 的"用户随机性占了组内 reward 差异的大头"对 Qwen
   不成立；文字分叉也不等于 reward 方差。v3 的混合题数是 22/34/25/16/23，README 随机性表里的是 v2 数字。
1. **新颖性。** P-GRPO 也是按用户组缩放（已在 [related-work.md §2](related-work.md) 更正），与
   [appendix-method-draft-16.11.md](appendix-method-draft-16.11.md) 的按用户逆方差加权很接近。如果采用
   [problem-and-plan.md §4](problem-and-plan.md)，更直接的比较对象是 utterance 级
   Q/V（ArCHer、SWEET-RL），原文尚未核实。
1. **critic 前提。** EV>0 只是弱筛查（Instruct step 90 的 EV 为正，但 MSE
   高于目标方差）；[problem-and-plan.md §4](problem-and-plan.md)
   需要的是用户回复边界处的校准。[ev-ceiling.md](../critic/ev-ceiling.md) 的"首 token
   上限"是"只按题目身份预测"的上限，不是 critic 的上限：首条用户消息每次都不同，可能透露信息。
1. **外推性。** 只有一个 actor、一个 benchmark；机制强烈依赖领域：Retail 的用户致败占失败的 66%，Airline 只占 19%。对这个
   actor，agent 失败（204）多于用户失败（168）。
1. **结果选择。** Turbo 首跑和重跑的差异归因于方舟服务异常，是合理推断，但充值和时间不是随机干预；应事前规定重跑规则，保留所有 attempt。

## 6. 讨论后的决定与要做的实验（2026-10-13）

### 6.1 决定

- **研究对象：真实用户的不可靠反馈。** 模拟器是可控的代理（[problem-and-plan.md §1](problem-and-plan.md) 决策
  15）。真人也会确认后离开、改主意、不给信息，不能假定用户质量高。
- **改 prompt 的定位**：不是"修用户"，而是构造用户的手段之一。换模型或改 prompt / persona
  产生配合与不配合、好与坏的用户；按概率注入固定错误行为（如确认后离开）产生可精确控制的缺陷。前者更自然，后者用于受控对照。质疑 4 因此不再是方法层面的
  baseline，只作诊断。
- **训练用不可靠用户，评测用可靠用户并检查 policy 合规。** 我们优化的是 agent 自身能力，不是在某个不可靠用户下的得分。
- **可比 baseline（单条 rollout）**：普通 SAO、REINFORCE++、按用户的滑动平均
  baseline、只看对话文本的规则审查（例如用户在授权的同一句里结束、写操作未执行，就丢弃或降权这条）或不看剧本的 judge。GRPO、RLOO
  和拒绝采样都需要重采样，不可比。
- **"差距缩到 5.6pp"不再作为证据。** 它按同一套标注删样本，差距缩小是标注的必然结果，属于循环论证；改用反事实回放（X4）。

## 7. 预实验候选（2026-10-14）

目的：在 X1、X2 这类正式训练之前，用轻量的检验巩固动机里的每一环，或者尽早发现某一环站不住、需要改动机。每条都写明结果分别意味着什么。动机各环的编号对应
`problem-and-plan.md` §1 的问题陈述：

- C1：模拟器的缺陷能代表真实用户的不可靠行为。
- C2：用户造成的失败把负信号落在 agent 的正确行为上。
- C3：伤害分两种，(a) 只增加方差，(b) 用户出错随 agent 说法变化，导致学错方向。
- C4：要在可靠用户上评测 agent 自身能力，并检查 policy 合规。
- C5：单条 rollout 下要区分"用户错"和"用户难"。
- C6：16.13 的方法依赖 critic 在用户回复边界上预测准确。

| M3  | C3(b) 的启发式                   | 在正在跑的 SAO 正式训练（`sao-mix-formal`，已有 31 步）的 `tau2-trajectories` 上，按训练步统计写前确认率、未确认就写的比例、确认后用户离开率；旧 GRPO formal-v2 做同样统计作对照                                           | 确认率随训练下降，是第 (b) 种伤害的初步迹象；不变也不能否定 (b)，因为训练步数少、用户是 DeepSeek，只算弱证据                                               |

### 7.2 第二档：少量 API，不需要 actor

| #   | 检验的环节              | 做法                                                                                                                                                                                                                                                         | 结果怎么读                                                                                                                                                                                                                                     |
| --- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M4  | C3：伤害是 (a) 还是 (b) | 从 v3 轨迹里取 agent 请求确认的前缀，成功和失败的都取，避免只挑 U1；同一模拟器（Turbo、Lite、DeepSeek，GLM 作对照）重采样下一句用户回复 8 次，测离开率。再把 agent 的确认语按 2–3 种固定模板改写（例如逐条列出 / 一句话概括 / 明确说"确认后我才执行"），重测 | 比较两种方差：同一前缀内的方差（换前缀之前就已存在的随机性，16.13 能处理的那部分），以及不同说法之间的离开率差异。说法几乎不影响离开率时，(b) 不成立，动机收窄为方差和样本效率，16.13 对症；说法影响明显时，(b) 成立，16.13 不够，需要单独处理 |

规模：约 100 个前缀 × 8 次 × 3 种说法，约 2,400 次单轮用户调用，走火山订阅。只需要用户模拟器，不需要 actor 和 GPU，要写一个直接调
`user_simulator.py` 的小脚本。

### 7.3 第三档：需要 GPU 或新代码，排在 critic 修好之后

| #   | 检验的环节                      | 做法                                                                                                                                                        | 结果怎么读                                                                                                                       |
| --- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| M5  | C2，非循环地测"用户致败"        | 反事实回放（X4）：在用户出错前截断，换一句用户回复，actor T=0 续跑。先取 30–60 个用户致败的 episode                                                         | 救回率高，"用户造成失败"成立；救回率低，说明 agent 后面也会失败，用户致败的比例被高估，要改证据表述。需要先写"从中途续跑"的代码  |
| M6  | C6                              | 用 M4 的重采样结果当真值：在同一批前缀上读 critic 在用户回复前的预测，和经验上的"不离开概率 × 后续成功率"比较。可以作为 critic 离线预实验之后的 E10         | critic 在边界上校准，16.13 的前提成立；不校准时先修 critic，不比较方法                                                           |
| M7  | C2 在我们实际用的算法里是否成立 | 用 critic 第 55 步的 checkpoint 重算 SAO 正式训练 rollout 的 advantage，统计负 advantage 质量有多少落在规则识别出的用户失败上（14.3 的 29% 是 GRPO 下的数） | SAO 的 critic 已经吸收了用户失败（这些 episode 上 advantage 很小）时，污染比 GRPO 小，动机要重新估计；仍然大时，C2 在 SAO 下成立 |

### 7.4 优先级（2026-10-14 修订）

- **M1–M3 降为可选，不单独排。** 它们回答的是设计问题（规则 baseline 多强、合规指标是否稳定），不增加动机的说服力：M1 在实现规则审查 baseline
  时自然得到，M2 在搭 X1 的评测时顺手验证，M3 只是弱证据。
- **M4 保留为低成本选项。** 它不加说服力，但决定主张是"降方差"还是"纠偏"，避免方法与问题不对应；X1 的写前确认率也能回答同一问题，只是更晚。
- **动机部分的首选预实验是 X1 的缩小版**：复用 SAO 配置，用户侧加"确认后按 20% 概率离开"的开关，开与关各跑 20–30
  步、部分训练题，在固定可靠用户上评测并看写前确认率。它直接检验唯一缺的一环"伤害训练"。前提是 critic 和 SAO 本身能学到东西（critic
  离线预实验正在处理），否则差异会淹没在训练无效里。
- M5–M7 不变，排在 critic 有结论之后。
