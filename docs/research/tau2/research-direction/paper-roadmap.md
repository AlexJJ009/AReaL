## 1 故事线

论文正文按完整的动机链写，语气自信；证据由实验逐环补齐（§2）。动机写清楚、逻辑不跳步，比在正文里自我设防更重要。自查和审稿式质疑只留在本文和 motivation
review 里，不进论文。

1. **场景。** 多轮、带工具的客服 agent 越来越依赖 RL 训练。在这类任务里，结局 reward 由 agent 和用户共同决定，用户不是被动的评测者。
1. **用户不可靠是常态。** 真人会在确认的同一句里离开、中途改主意、记错信息、没办完就走。LLM 用户模拟器同样如此，而且不同模拟器的错法不同。同一个 agent
   只换用户模拟器，Retail 成功率从 85.0% 降到 65.0%；失败里用户造成的比例从 29% 升到 80%，而 agent 自身的失败数几乎不变（图 1）。
1. **对 RL 的伤害。** 用户造成的失败让 agent 在每一步都做对的情况下拿 0 分，负优势落在 agent 此前的正确行为上，比如守规矩的写前确认。伤害有两种：
   - 用户出错与 agent 怎么做无关：信号被稀释、方差变大，同样的预算学得更少。
   - 用户出错随 agent 的说法变化：策略被推向违反 policy 的捷径，例如少确认、直接写。这是学错方向。
1. **现有做法依赖在线场景拿不到的条件。** 带剧本的 judge 整条 mask（AutoForge）、换或微调更强的用户（AReaL-SEA）、组内多条 rollout
   做基准或过滤（GRPO、GiGPO、IAPO），都要求能重复对话或查看用户的隐藏目标。真实用户的每次对话只发生一次，没有剧本，同一题只有一条 rollout。
1. **我们的设定与做法。** 单条 rollout、带 critic 的 actor-critic（SAO）。只用线上可观测的信息（对话文本、结局
   reward、同一用户的历史），把用户回复带来的意外与 agent 自己的贡献分开计分。具体方法待定，候选见
   [problem-and-plan.md §4](problem-and-plan.md)。
1. **评测原则。** 我们优化的是 agent 自身的能力。训练时面对不可靠用户，评测用固定的可靠用户，并直接检查 policy 合规（写前是否确认）。
1. **模拟器的角色。** 模拟器是可控的代理：换模型或 persona
   构造可靠度不同的用户，按概率注入固定缺陷做受控对照。每类模拟缺陷对应一种真人行为：确认后离开（U1）、改主意或记错（U3）、没办完就走（U4b）。

**分工原则**：Preliminary 只放我们自己的测量，回答"现象是什么"。Related Work 回答"别人在什么前提下解决了相邻的问题"。两节不重叠：同一篇工作，在
preliminary 里最多作为一句佐证出现，在 related work 里才讨论方法和前提。

## 4 Preliminary：图 1

源文件：`paper/figures/user_sim_retail.tex`（pgfplots，Overleaf 直接编译），预览图在本机 Overleaf 目录的
`figures/user_sim_retail_preview.png`。

设计：

- 左侧是表格，列为 Retail mean@4、pass^4、用户致败占失败的比例。

口径：

- 归因来自 v3 case study 的 `labels.jsonl`，每个失败只计一个主原因。
- Lite、Turbo、Qwen 各有 1 个 episode 原来靠重跑才成功，按新规则记为超出上下文的失败，归入 agent 一栏。

图要传达的信息：

- agent 自身的失败数在 10–15 之间，几乎不随用户变化；分数差几乎全部来自用户。
- 不同模拟器的错法不同：Doubao 系列在确认的同一句里结束，Qwen 用户偏离任务条件。

**正文里的写法**：

- 讲"同一 agent，换用户后 Retail 成功率从 85.0% 降到 65.0%，pass^4 从 72.5% 降到 30.0%"。
- 按题配对 bootstrap（10,000 次，Retail 40 题，严格计分）：GLM 对 Turbo −20.0pp \[−32.5, −7.5\]，GLM 对
  Qwen −20.0pp \[−33.1, −6.2\]，DeepSeek 对 Turbo −15.6pp \[−26.3, −4.4\]。85.0% 到 65.0%
  这个对比本身是显著的，正文可以直接用。脚本：[../scripts/rescore/boot.py](../scripts/rescore/boot.py)。
- 实验细节放在附录：单次运行、标注方式、bootstrap 方法。

Airline 不进主图。Airline 的失败以 agent 为主，用户致败只占 19%；可以在附录给全领域版本。
